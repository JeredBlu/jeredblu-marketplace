# Red flags: what each scan category means

For each `scan.sh` category: why it matters (plain English), common **legitimate** reasons (to dismiss false positives), and the tell that makes it bad.

| # | Category | Why it matters | Usually fine when… | Bad when… |
|---|---|---|---|---|
| 1 | Remote execution | Downloads code at runtime that you never reviewed and runs it | Docs showing *the user* how to install (read what the script does) | The program/installer itself fetches and runs a script, esp. from a non-project domain or raw IP |
| 2 | Install hooks / quarantine bypass | Code runs automatically when you install; removing quarantine can bypass first-launch Gatekeeper assessment | `postinstall` compiles a native addon (`node-gyp`); cask strips quarantine because the app isn't notarized **and says so** | Hook downloads things, reads files, or contacts network; quarantine stripped silently |
| 3 | Persistence | Keeps running after reboot / at login | "Start at login" toggle the user opts into; `SMAppService` login item | Silent LaunchAgent/Daemon, cron job, shell-profile append the user wasn't told about |
| 4 | Privilege | Admin/root can change anything on the machine | Dev/CI scripts (`.github/`), documented one-time helper installs | App asks for admin at runtime with no clear reason; disables SIP/Gatekeeper; resets TCC for other apps |
| 5 | Destructive | Could delete data | Cleanup of its own build/cache dirs | Paths outside its own dirs, `$HOME`, `/`, disks |
| 6 | Credential access | Can read passwords, tokens, keys, browser data, crypto wallets | Password managers / git tools reading **their own** config the user pointed them at | A tool with no credential purpose touching `~/.ssh`, `~/.aws`, browser profiles, keychain, wallets |
| 7 | Surveillance capability | Can see keystrokes, screen, clipboard, mic, camera | Window managers (mouse monitors), screenshot tools (screen), clipboard managers (clipboard) | Capability unrelated to purpose; keyboard taps in a non-input tool; any capture + network send |
| 8 | Telemetry | Usage data leaves your machine | Opt-in, documented, disable flag exists, no personal data | On by default, undisclosed, or includes file paths/usernames/content |
| 8b | Telemetry off-switches | Tells you whether telemetry is opt-out (on by default) or opt-in | Documented env var/flag, respected everywhere | Switch exists but some code paths ignore it; off-switch undocumented |
| 9 | Phone-home endpoints | Classic exfiltration channels | Test fixtures, docs examples | Discord/Telegram webhooks, paste sites, tunnels, raw public IPs in shipping code |
| 10 | Auto-update | Future versions install without re-review | Sparkle with signed appcast over HTTPS; user can disable | Unsigned updates, HTTP feeds, updates fetched from a domain the project doesn't own |
| 11 | Opens URLs | Can push you to pages | "Help"/"Sponsor" menu items the user clicks | Opens pages on launch/install unprompted |
| 12 | Auto-star / follow | Uses YOUR GitHub token to boost the author — abuse of your account | Never legitimate without an explicit, opt-in prompt | Any silent call to `/user/starred` or `/user/following` |
| 13 | Self-promo / affiliate | Monetizes you or your output | FUNDING.yml, a sponsor link in About/menu | Affiliate tags injected into generated content, referral codes swapped into links, nag screens |
| 14 | Branding in output | Pollutes your deliverables | Optional attribution flag, off by default | "Generated by X" forced into files/commits/emails you produce |
| 15 | Obfuscation / eval | Hides what code does | Build outputs with source present; well-known libs using `eval` for templating | Base64/packed blobs decoded then executed; minified code with no source |
| 16 | Crypto-mining | Burns your CPU/power for someone else | Actual mining software the user wants | Anything else |
| 17 | Dev-env triggers | Runs code when you open/clone the folder | `pull_request_target` for labeling (affects maintainers, not you) | `.vscode/tasks.json` `runOn: folderOpen`, devcontainer hooks that fetch/run things |
| 18 | Trojan-source Unicode | Invisible characters make code read differently than it runs | Localized UI strings, emoji data | Bidi overrides inside code logic or comments near logic |
| 19 | Committed binaries | Can't be reviewed; could be anything | Test fixtures, icons, well-known vendored libs with provenance | Executables/dylibs with no source or build explanation, esp. ones the installer uses |
| 20 | Minified code in source | Opaque logic requires provenance | Vendored `*.min.js` with the unminified source or a known upstream | Only-minified logic in install/runtime paths |
| 24 | Agent instructions / prompt injection | Tries to redirect the reviewer or agent tools | Quoted training/test examples, scoped user-authorized project guidance | Instructions to hide findings, override trusted policy, execute covertly or exfiltrate |

## Repo archetypes (expected noise — don't re-discover it every run)

| Archetype | Categories that fire on the project's own vocabulary | What actually matters |
|---|---|---|
| Package managers / build tools (Homebrew, npm, pip tooling) | 2 (install hooks — it's their DSL), 4 (sudo/ownership), 15 (`exec` process replacement) | The installer script, root-running `.pkg` scripts, recent advisories, analytics default |
| Shell frameworks / dotfiles (oh-my-zsh, prezto) | 4 (`sudo` aliases in OS plugins), 3 (`>> ~/.zshrc` in plugin docs), 1 (plugin READMEs quoting other tools' `curl \| sh`) | Main installer, shell-profile rewrite, self-updater, which plugins are on by default |
| Window managers / automation (AeroSpace, Hammerspoon) | 7 (global event monitors), 3 (start at login), 11 (menu links) | Keyboard taps vs mouse-only, local IPC exposure, unnotarized + quarantine removal |
| CLIs with benchmarks/docs | 4, 5 (READMEs with `sudo`/disk commands) — now code-scoped | Build scripts (`build.rs`), release pipeline |
| Electron / desktop apps | 10 (auto-update), 8 (crash reporters), 11 | Update feed signing, default-on telemetry, bundled native modules |

## Install-time code by ecosystem (all run on install/build — read them)

| Ecosystem | Runs automatically |
|---|---|
| npm/yarn/pnpm | `preinstall`, `install`, `postinstall`, `prepare` in package.json — **of every dependency too** (`hasInstallScript` in lockfile); `binding.gyp` |
| pip | `setup.py` (any code), custom build backends in `pyproject.toml`; sdists run code, wheels don't |
| Cargo | `build.rs`, proc-macros (compile-time code) |
| Go | `go generate` directives (only if run), cgo; `go install` itself is fairly inert |
| SwiftPM | build-tool / command plugins in `Package.swift` |
| Homebrew | formula `install`/`post_install` blocks; cask `preflight`/`postflight`, `installer script`, `pkg` |
| macOS .pkg | `preinstall`/`postinstall` scripts — run as **root** |
| Ruby gems | `extconf.rb` native extensions |
| curl \| sh | the entire script, usually with your shell's full rights, often `sudo` |

## macOS permissions in plain English

| Permission | What it lets the app do |
|---|---|
| Accessibility | See and control every window and UI element; click and type as you |
| Input Monitoring | See every key you press, in every app |
| Screen Recording | See everything on your screen |
| Full Disk Access | Read nearly every file, incl. Mail, Messages, Safari data |
| Automation (Apple Events) | Control other apps (e.g. tell Finder/Mail to do things) |
| Camera / Microphone | Obvious — check for an in-app indicator and purpose |
| Admin password prompt | Can change anything on the system |
| Quarantine removed (`xattr -d com.apple.quarantine`) | Can bypass first-launch Gatekeeper assessment; not every macOS protection |
| Unnotarized | No verified notarization for this artifact; not proof of malware or absence of all platform scanning |

## Provenance red flags

- Repo renamed or transferred recently (name mismatch in `repo_meta.py`); new maintainer who immediately touches install/release code (event-stream pattern).
- Owner account new, or old but dormant then suddenly active.
- Very high stars but few forks/issues/contributors, or stars/day wildly out of line with discussion elsewhere.
- A look-alike repo (same name, different owner) — confirm the user has the original; check links in the README point to the same owner.
- Release assets uploaded by a person with no checksums — you can't tie the binary to the source.
- Published package (npm/PyPI) whose `repository` points elsewhere, or whose version isn't tagged in the repo.
- README install command downloads from a domain the project doesn't clearly own.
- **Impostor download sites** ranking in search (`<name>.org`, `<name>-download.com`) the project doesn't own — always state the official source.
- Issues reporting AV/EDR detections: read them — most are false positives on unnotarized tools, but the maintainer's response is itself a signal.
